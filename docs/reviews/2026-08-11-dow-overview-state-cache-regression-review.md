# 道氏监控列表状态缓存回归独立复核

## 需求到证据

- `REQ-DOW-MONITOR-LIGHTWEIGHT-LIST-OVERVIEW-001`：实现仍返回同一轻量 DTO，只改变状态文件读取方式；API 回归和缓存外部变更用例均通过。

## 下层语义复核

测试直接统计 `_load_states()` 调用，而不是仅比较页面快照。它证明未变化文件不重复解析、外部修改可见且只重载一次。写路径在锁内刷新、落盘和更新签名，避免缓存优化引入丢更新。

## 边界与风险

- 未修改道氏形态、买卖点、分钟计算、六指标、通知选择或 WebSocket 订阅规则。
- 文件签名采用大小与 `st_mtime_ns`，外部内容若在同一纳秒内以相同长度覆盖属于文件协议外的极低概率风险；正式写路径仍使用原子替换。
- 候选验证不能替代正式环境 ClickHouse 能力和页面时效验收，生产证据完成前不得把“3018 端口已开”表述为修复完成。

## 生产复核

独立复核确认正式容器加载的是修复文件，ClickHouse 分钟能力为有效的 4-capability 启动，而不是先前数据库不可用时的降级启动。浏览器刷新得到 9 行和 2.105 秒 TTFB，满足列表性能门槛。页面同时暴露部分指标的真实陈旧时间；因此本修复只关闭列表卡死/状态文件重复解析问题，不错误宣称道氏分钟计算产出已经恢复。

结论：列表缓存回归已经通过代码、真实文件、正式能力和浏览器端到端验收。道氏分钟结果陈旧保留为下层计算链路的独立未完成项。
